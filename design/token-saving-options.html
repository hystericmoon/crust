Where the tokens go, and what to change

Every step Claude takes (reading a file, running tests, writing a reply) re-reads everything already in the conversation. So the cost of a step is roughly the size of what Claude is carrying, and a feature costs the area under that line. The cheapest fixes keep that line low.

A. Slim start: rules load only when needed

today
~250k
after
~244k

What changes

  • spec.md stops loading on every step. Its content format moves into a Crust skill (a rulebook Claude opens only when a feature touches page JSON).
  • The session start and end-of-feature routines become skills too, so CLAUDE.md shrinks to a short index.

Trade-off

  • Small saving per step (~6k), but on every step of every feature.
  • Risk: a rule Claude forgets to open. The skill descriptions name when to open them, which limits this.

What changes

  • Big searches and reads go to a helper agent; only its conclusion comes back.
  • Tests and builds report a short summary (failures only), not full logs.
  • At about 200k, I write my notes to HANDOVER.md and ask you to /clear, then paste the usual message.

Trade-off

  • Biggest saving: roughly 40–50% on long features.
  • Costs you one extra clear on long features (the same 2 steps you already do).

What it does

  • Builds a graph of files, functions and docs that Claude queries instead of opening files.
  • Its big claims (up to 70× fewer tokens) are for 500+ file codebases that the agent doesn't know.

Why not here

  • HANDOVER.md already tells each feature exactly which files matter, so little time goes on finding code.
  • Cloud containers start fresh: it would need installing and rebuilding each session, and reading docs into the graph costs tokens itself.
