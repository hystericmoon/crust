Publish to Cloudflare Pages or Netlify

In the app, a site can go live on a free host the person already has: Cloudflare Pages or Netlify. They make a token on the host's website once (the app walks them through it), paste it, pick an address, and from then on Publish puts the site online in one press.

The token is kept in the computer's keychain (Mac: Keychain, Windows: Credential Manager), never in the site folder, so duplicating or sharing a site never shares the token. Each site remembers its own host and address.

Why A

Visible choice

The two hosts sit on the card before anything is set up, so people see what's possible without hunting (Nielsen: recognition rather than recall). B hides it in settings; C hides it behind a press.

Setup in context

Connecting happens at the moment of intent, where publishing lives. Afterwards the card says plainly where the site goes and when it last went there: visibility of system status.

Guided, not a form

Making a token is the hard part for a non-developer. A short step dialog (open the host's page, which boxes to tick, paste, check) beats three empty fields. It checks the token right away, so mistakes show at step 2, not at publish time.

Accessibility

  • Host tiles are real buttons (44 px tall or more), reachable with Tab; the dialog traps focus, Escape closes it, and focus returns to the tile.
  • The token field is a labelled password field with paste allowed (WCAG 3.3.8: no memory test); errors are tied to it with aria-describedby and focus moves to it.
  • Progress and results are announced through the card's live status; failures use an alert.
  • “Open … ↗” buttons say they open the web browser, for screen readers too.
  • Colours from the app's existing tokens (all pairs ≥ 4.5:1); the green dot always has the host's name next to it, never colour alone.
