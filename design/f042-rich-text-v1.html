Rich text in Text blocks

Bold, italic, links, bulleted and numbered lists inside a Text block, with a small toolbar and keyboard shortcuts. Two places the toolbar could live. Try them: the mock below is live, so select words and press the buttons or ⌘B.

Where you format

The Text field in the right-hand panel becomes a small editor with its toolbar on top. The canvas updates as you type, like every other field.

Trade-offs

A · Recommended

Toolbar on the Text field

  • Works the same everywhere: builder panel, Quick edit on the phone, posts.
  • One reliable spot for keyboard and screen reader users: Tab into the field, the toolbar is one Tab stop with arrow keys.
  • Never covers the page you're designing.
  • You look at the panel while typing; the canvas follows a moment later.
B

Toolbar on the canvas

  • Type right on the page; feels closest to Webflow and Framer.
  • Puck drags and selects blocks on the canvas, so typing there fights with dragging; needs more work and more testing.
  • The floating bar covers text above, and is hard to reach on a phone.
  • Could come later on top of A: same saved format.

States and rules

Links

Checked like every link

Page addresses (/menu), https://, mailto: and tel:. Anything else is refused in the form, and again when saving and publishing. Renaming a page updates links inside text too.

Headings

No headings inside text

Headings stay their own block, so the heading-order and one-h1 checks keep working. Bold is for emphasis, not titles.

Paste

Pasting keeps the basics

From Google Docs or a website: bold, italic, links and lists come along; fonts, colours and sizes are dropped, so the site's style wins.

Existing pages

Nothing to redo

Text you already wrote becomes paragraphs in the new format the next time the page is opened and saved. Until then it publishes exactly as before.

Alignment

Align and tone stay

Left, centre, right and Muted still apply to the whole block. Lists in centred text stay left-aligned inside, so bullets line up.

Not in this feature

Kept out on purpose

Underline (reads as a link), colours, font sizes, tables, images in text. They'd fight the design tokens.

On the phone (Quick edit)

Direction A works the same in Quick edit: the Text field gets the same five buttons, 44 px tall.

How it's saved

As structured text in the page file, never as HTML. Each paragraph or list is listed with its words and their style, so it can't carry scripts or stray formatting, and the published page is plain HTML with no JavaScript.

"text": { "rich": 1, "blocks": [
  { "type": "p", "children": [
      { "text": "Fresh bread " },
      { "text": "every morning", "bold": true },
      { "text": " from 7. See the " },
      { "text": "menu", "href": "/menu" }, { "text": "." } ] },
  { "type": "ul", "items": [ [ { "text": "Sourdough" } ], [ { "text": "Rye" } ] ] }
] }

Editor: Lexical (MIT, free), which the spec planned. Puck's own rich text field stores HTML, which the rules don't allow.
