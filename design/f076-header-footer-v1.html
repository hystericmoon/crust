A header and footer that look made for the site

Six header layouts, a header that sits clear on the hero photo, dropdown menus, a phone menu that slides in from the side, an optional top bar, and a footer you build from blocks like any section. All of it works with the keyboard and screen readers, and needs no scripts on the site.

Clear on a hero photo
Top bar
Stays at the top (sticky)
  • Layout pictures first. The biggest visual decision is one click, made by recognising a picture rather than combining alignment settings (recognition over recall).
  • The menu stays a list, with the same Move up / down buttons as today. Nesting is one more button pair, so dropdowns work by keyboard in the builder too. Limited to one level: deeper menus test badly on phones (NN/g on mega-menus and mobile navigation).
  • Footer from blocks reuses linked sections (F043), which you already know. Its contrast, headings and links get the same checks as any page. The simple footer stays for quick sites.
  • Header stays structured, not free-form. Then the skip link, landmarks, sticky offset, phone menu and focus order are guaranteed on every site.

B · Header and footer both built from blocks

Header (linked section)

New blocks: Logo, Menu, Search link. You arrange them in Columns.

  • Total freedom: any arrangement, two rows, icons, a phone number in the header. This is how YOOtheme's builder header works.
  • Easy to break: a header without a menu, with the menu hidden on phones, or with two h1s. Crust would need many new checks to keep it accessible.
  • The phone menu and sticky behaviour have to work around whatever you build, so they get less reliable. Work: very large.

Accessibility, built in

Landmarks
One "Main" navigation, a banner and a contentinfo landmark. Footer link groups keep their headings.
Dropdowns
A real button with aria-expanded (native <details>). The parent's own page, if it has one, is the first link inside. Escape closes it and returns focus to the button.
Phone menu
Opens from a 44 px Menu button and closes with ✕ (44 px) or Escape. Focus moves through the panel in order. Nothing behind it moves.
Top bar and clear header
Section styles carry the colours. On a photo, the hero's own tint keeps the header text readable; on pages that don't start with one, the header stays solid.
Keyboard in the builder
Menu nesting is done with buttons, not dragging (CLAUDE.md: a keyboard way for every drag).
Without scripts
Everything above works with plain HTML and CSS. A tiny optional script only adds "Escape closes" and "click outside closes", and only on pages with a dropdown or the side panel.
